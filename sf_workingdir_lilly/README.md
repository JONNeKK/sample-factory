# Research Project Lilly Reisig

This file contains the modifications for my research project Echo State Networks as CA3-inspired models in spatial navigation tasks. 

The model was created by Xiao-Xiong Lin. In this reaerch project the core of the model was varied and the effects on performance analyzed.

### Added Parameters
which parameters were added to custom_params.py
* spectral_radius: which spectral radius do the ESNs have
* sparsity: sparsity of the used ESNs
* weight_trial: which weights should be used
* weight_folder: out of which folder are the weights extracted
* isolated_features: determines whether the input and recurrent weights are generally fixed for all features
* fixed_wih: determines whether the input weights are fixed
* fixed_whh: determines whether the recurrent weights are fixed

### Relevant Changes
In this section I will list the important files and briefly describe the changes made to them.

* **cutstom_weight_generator.py**: The core contains a reservoir-style network. I changed it to ESNs. This file was used to generate the fixed input and recurrent weights. It is possible that every input feature has different or the same input and recurrent weights \\
Mainly the recurrent weights in the weights folder were used. In this folder are also weights with different sparsities and weights with different input weights for different features. These were not used for simulations. \\
weights1.2 contains weights with spectral radius 1.2, these were not used for simulations. \\
weights_shrunk_esn contains different weights for a smaller network size of 381 with different spectral radii between 0.3 and 2. \\
weights_shrunk_esn contains weights for 50 different ESNs with the smaller network size of 381. The spectral radius is fixed to 1.4.

* **custom_core.py**: There are different core options with different ESN functionalities. \\
**FixedESNWithBypassCore**: generates an ESN when the core is created. The weights are not saved. \\
**FixedESNWithBypassCorePreGeneratedWeights**: core is an ESN that uses the weights that were previously created. The weights of the RNN are replaced with the weights generated by the custom_weight_generator and fixed, so that they are not changed during training. \\
**FixedRNNWithBypassCoreLORA**: we use a fixed sequence reservoir as Lin before but add Low-Rank Adaptation. This was done by creating a custom class **custom_rnn** in which there are two parameters that are not fixed during training to enable the Low-Rank Adaptation to be learned. \\
**FixedESNWithBypassCoreRandomNetworkLORA**: uses the same method with pregenerated weights as **FixedESNWithBypassCorePreGeneratedWeights** however, there is Low-Rank Adaptation too, the same as here **FixedRNNWithBypassCoreLORA**

* **LoRA Adaptation**: **custom_rnn** realizes the LoRA Adaptation during training, **FixedRNNWithBypassCoreLORA** and **FixedESNWithBypassCoreRandomNetworkLORA** are the cores that include LoRA adpation on the recurrent weights. 

### Relevant Simulations
naming: Name + number of simulation overall

The relevant simulations with smaller networks (381):
* ESNShrunk26: different run trials with different spectral radii (esn_run_shrunk_network2.py)

Relevant simulations with full network size (1149):
* ESNDifferentWeightsIsolatedFeatures44: run all of the stable networks over 3 different seeds with 4 policy workers, this is the main run used for the analysis in my report. (esn_run_diff_weights10.py)
* RNNRandomLORA47: run with all stable networks over 3 seeds and 4 policies. LoRA rank 1 is learned for each weight trial in each seed. This is the LoRA simulation used for the analysis in my report. (esn_run_diff_weights_randomLORArnn5.py)
* RNNRandomLORA48: run with all stable networks over 3 seeds and 4 policies. LoRA rank 16 is learned for each weight trial in each seed. (esn_run_diff_weights_randomLORArnn6.py)
* RNNLORA45: We have a pre-wired fixed sequence reservoir. Throughout training a LoRA rank 1 is learned. (esn_run_diff_weights_LORArnn2.py)
* RNNFixedSequenceLORA46: We have a pre-wired fixed sequence reservoir. Throughout training a LoRA rank 16 is learned. 

### Analysis
The data analysis that I refer to in the report is in the analysis folder. It contains two main sections. In the network analysis folder, the memory capycities of the reservoirs was analyzed. In the performance analysis folder, the performance of different agents with different cores was analyzed and correlated with the memory capacity measures.

#### network analysis
Memory capacity analysis simulation 44:
Activity norm, subspace expansion: orth_vec_analysis_for_diff_weights.ipynb
Orthogonalized subspace method, Summed Singular Components and participation ratio: memory_capacity_analysis.py \\
Get and save all of the trained LoRA components for different simulations.
See whether LoRA increases memory capacity (mc_comparison.py).
Memory capacity analysis ESNs with LoRA: memory_analysis_random_network_47.ipynb & memory_analysis_random_network_48.ipynb

#### performance analysis
The data extraction files extract the raw performance score from W&B and save it to a pickle file in the data folder. The data analysis folders, are the specific analysis of the performance of that simulation. Specifically relevant for my report is mainly:
* the analysis of simulation 44 (ESNDifferentWeightsIsolatedFeatures44)
* **performance_comparison**: compare performance between the ESN and the pre-wired fixed-sequence reservoir with and without LoRA
